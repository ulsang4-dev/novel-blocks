# 소설 덩어리 집필 앱 — 설계 문서

- 작성일: 2026-09-28
- 상태: 사용자 검토 대기

## 1. 목적과 범위

소설을 "덩어리" 단위로 구조화하고, 각 덩어리에 플롯을 넣어 가며 집필하는 **개인용** 웹앱.
PC와 휴대폰 모두에서 동작하고, 데이터는 사용자 본인의 구글 드라이브에 저장·동기화된다.

### 성공 기준
- 템플릿을 골라 새 작품을 만들면 플롯 공식에 맞는 빈 덩어리가 자동 생성된다.
- 덩어리를 막 → 장 → 씬 위계로 자유롭게 추가·이동·분할·병합할 수 있다.
- 씬 카드를 보드에서 드래그로 재배치할 수 있고, 카드마다 플롯 요약과 본문을 쓸 수 있다.
- PC에서 쓴 내용이 폰에서 보이고, 그 반대도 된다. 오프라인에서도 쓸 수 있다.
- 버튼 한 번으로 원고가 구글 문서로 드라이브에 만들어진다.
- 어떤 경우에도 쓴 글이 조용히 사라지지 않는다.

### 제외 (이번 버전)
공동 집필, 다중 사용자 공개, AI 글쓰기 보조, 인물 사전, 세계관 위키, 네이티브 앱스토어 배포.

## 2. 사용자와 제약
- 사용자: 본인 1명. 본인 구글 계정으로 로그인.
- 비용: 서버 없음. 정적 호스팅(GitHub Pages) + 구글 드라이브 API.
- 구글 OAuth 앱은 "테스트" 상태로 두고 본인 계정만 테스트 사용자로 등록 → 심사 불필요.
- 드라이브 권한 범위: `drive.appdata`(앱 전용 숨김 폴더), `drive.file`(앱이 만든 파일만). 사용자의 다른 파일에는 접근하지 않는다.

## 3. 데이터 모델

```ts
type Novel = {
  id: string;
  title: string;
  templateId: string;
  rootIds: string[];              // 최상위 덩어리 순서
  nodes: Record<string, Node>;    // 모든 덩어리/씬
  createdAt: number;
  updatedAt: number;
  exportDocId?: string;           // 내보낸 구글 문서 ID (덮어쓰기용)
  outlineDocId?: string;          // 플롯 개요 문서 ID
};

type Node = {
  id: string;
  kind: 'block' | 'scene';        // scene은 자식을 갖지 않는다
  title: string;
  plot: string;                   // 이 덩어리/씬에서 일어나야 할 일
  guide?: string;                 // 템플릿 안내 문구 (읽기 전용 힌트)
  color?: string;                 // 색상 라벨
  childIds: string[];             // block만 사용, 순서 보존
  // scene 전용
  characters?: string[];
  memo?: string;
  body?: string;                  // TipTap HTML
  status?: 'idea' | 'draft' | 'revise' | 'done';
  updatedAt: number;              // 노드 단위 수정 시각 (병합에 사용)
};
```

- 위계 깊이 제한 없음. 막/장 구분은 이름일 뿐 구조상 모두 `block`.
- 글자 수는 저장하지 않고 `body`에서 계산한다.

### 템플릿 (기본 제공)
| ID | 이름 | 초기 구조 |
|---|---|---|
| `blank` | 빈 템플릿 | 덩어리 1개 |
| `kishotenketsu` | 기승전결 | 기 / 승 / 전 / 결 |
| `three-act` | 3막 구조 | 1막(설정, 발단) / 2막(대립, 중간점, 위기) / 3막(클라이맥스, 결말) |
| `save-the-cat` | Save the Cat 15비트 | 15개 비트를 3막 아래에 배치 |

각 덩어리에는 `guide` 문구(예: "주인공의 일상과 결핍을 보여준다")가 들어간다.

## 4. 화면

1. **서재**: 작품 목록(제목, 수정일, 총 글자 수), 새 작품(제목 + 템플릿 선택), 삭제(확인 후).
2. **구조 보드**: 선택한 위계 단계의 덩어리를 가로 열로, 그 안의 씬 카드를 세로로 표시. 드래그로 순서 변경 및 다른 덩어리로 이동. 카드 클릭 시 플롯 요약 인라인 편집, 더블클릭/열기 버튼으로 집필 화면.
3. **목차**: 위계 트리. 추가(형제/자식), 이름 변경, 분할(자식을 두 덩어리로 나눔), 병합(인접 형제와 합침), 접기/펼치기, 드래그 이동.
4. **집필**: 중앙 본문 편집기(TipTap). 사이드 패널에 현재 씬 플롯 + 상위 덩어리들의 플롯, 인물 태그, 메모, 상태. 이전/다음 씬 이동. 글자 수 표시.

### 모바일 (폭 < 768px)
- 하단 탭: 서재 / 보드 / 목차 / 집필.
- 보드는 한 열씩 표시하고 좌우 스와이프로 이동.
- 집필 화면의 플롯 패널은 상단 접이식 영역.

### 디자인
흰 배경, 얇은 테두리 카드, 넓은 여백. UI는 고딕 계열, 본문은 명조 계열(Noto Serif KR). 포인트 색 1개. 시스템 설정에 따른 다크 모드.

## 5. 저장과 동기화

### 로컬 (IndexedDB)
- 모든 편집은 즉시 IndexedDB에 저장. 로그인/네트워크 없이 완전 동작.
- 작품별 레코드 + 마지막 동기화 기준본(`base`) 사본을 저장.

### 드라이브
- 작품당 `novel-<id>.json` 파일 1개를 appDataFolder에 저장.
- 업로드: 편집 멈춤 후 3초 디바운스.
- 다운로드 확인: 앱 시작 시, 창 포커스 복귀 시.
- 백업: 업로드할 때마다 이전 본을 `novel-<id>.backup-<timestamp>.json`으로 보관, 최근 10개 유지.

### 병합 (3-way, 노드 단위)
기준본 `base`, 로컬 `local`, 원격 `remote`를 비교한다.
- 한쪽만 바뀐 노드 → 바뀐 쪽 채택.
- 양쪽 모두 바뀌었고 내용이 같음 → 그대로.
- 양쪽 모두 바뀌었고 내용이 다름 → **충돌**. 사용자에게 두 버전을 나란히 보여주고 선택(로컬/원격/둘 다 보존). "둘 다 보존"은 원격 버전을 복제 씬으로 추가.
- 한쪽 삭제 + 다른 쪽 수정 → 수정 쪽을 살린다(글 유실 방지).
- 순서(`childIds`, `rootIds`): 한쪽만 바뀌면 그쪽 채택, 양쪽 다 바뀌면 원격 순서를 기준으로 로컬에서 새로 추가된 항목을 뒤에 붙인다.

### 상태 표시
"저장됨 · 동기화 중 · 오프라인 · 로그인 필요 · 충돌 있음"을 헤더 구석에 표시.

## 6. 내보내기
- 작품을 HTML로 변환(막/장 = 제목 레벨, 씬 = 본문)한 뒤 `mimeType: application/vnd.google-apps.document`로 업로드해 구글 문서로 변환.
- 드라이브 "소설 원고" 폴더(없으면 생성)에 저장. `exportDocId`가 있으면 해당 문서를 덮어씀.
- 선택: 플롯 요약만 모은 "플롯 개요" 문서도 같은 방식으로 내보냄.

## 7. 구성 요소

| 모듈 | 역할 | 의존 |
|---|---|---|
| `model` | 타입, 노드 조작(추가/이동/분할/병합/삭제), 템플릿 | 없음 |
| `storage/local` | IndexedDB 읽기·쓰기 | `model` 타입 |
| `storage/drive` | 구글 로그인(GIS 토큰), appData 업로드/다운로드, 백업 | 없음 |
| `sync` | 3-way 병합, 충돌 목록 산출, 동기화 스케줄 | `model`, `storage/*` |
| `export` | 작품 → HTML → 구글 문서 | `model`, `storage/drive` |
| `ui` | 서재/보드/목차/집필, 상태 표시, 충돌 해결 대화상자 | 위 전부 |

기술: React + TypeScript + Vite, `vite-plugin-pwa`, `@dnd-kit`, TipTap, `idb`, Vitest.

## 8. 오류 처리
- 토큰 만료: 무음 재발급 시도 → 실패 시 "다시 로그인" 배너. 로컬 작업은 계속.
- 네트워크 실패: 업로드 대기열 유지, 온라인 복귀 시 재시도(지수 백오프).
- 드라이브 용량/권한 오류: 원인 안내, 로컬 저장 계속.
- 손상된 원격 JSON: 무시하고 가장 최근 백업을 제안.

## 9. 테스트
- `model`, `sync` 병합 로직: Vitest 단위 테스트(충돌·삭제·순서 경우 포함).
- `export`의 HTML 변환: 단위 테스트.
- 드라이브 연동: 모의(mock) 드라이브 클라이언트로 동기화 흐름 테스트.
- UI: 로컬 개발 서버를 브라우저로 띄워 데스크톱/모바일 폭에서 수동 확인.

## 10. 배포
- GitHub Pages에 정적 배포.
- 사용자가 할 일: GitHub 계정, Google Cloud 프로젝트에서 OAuth 클라이언트 ID 발급(승인된 JS 출처에 배포 주소와 `http://localhost:5173` 등록), 본인을 테스트 사용자로 추가. 단계별 안내 문서(`docs/setup-google.md`) 제공.
- 클라이언트 ID는 환경 변수(`VITE_GOOGLE_CLIENT_ID`)로 주입.
